# Цикл Claude + Codex

## Когда применять

Перед постановкой задачи Codex, при чтении его отчёта, и всякий раз, когда после
его правок что-то не собирается. Скилл описывает не идею разделения ролей, а
конкретные грабли, на которые мы уже наступили.

## Рабочий режим (правило владельца)

**Работаю автономно, без остановок и вопросов — довожу до готового продукта и
проверяю сам.** Не ждать подсказок и не спрашивать разрешения между шагами:
планировать, отдавать Codex, собирать, ставить, проверять на устройстве, чинить
по кругу — до результата без багов и сбоев. Останавливаться только при реальном
внешнем блокере (нет доступа, нужен секрет/оплата, физическое действие на
чужом устройстве). Отчёт — по факту готовности, а не «жду отмашки».

**Тот же режим обязателен для Codex (он в подчинении).** Codex тоже работает
автономно до результата и ОБЯЗАН завершать каждый прогон явным вердиктом,
который возвращает Claude:
- `ГОТОВО` — сделано и самопроверено (tsc/тесты показаны), можно принимать;
- `СБОЙ / ТРЕБУЕТСЯ ДОРАБОТКА` — что именно не вышло, причина, что нужно.

Это handshake, а не вежливость: без явного вердикта прогон считается незавершённым.
Поэтому в КАЖДЫЙ промпт для `codex exec` добавлять требование: «Заверши ответ
одной строкой: ВЕРДИКТ: ГОТОВО или ВЕРДИКТ: СБОЙ — <причина>». Claude, приняв
`ГОТОВО`, всё равно перепроверяет сборкой (Codex не может проверить себя сам).

## Главное ограничение, определяющее всё остальное

**Codex не может проверить свою работу.** В песочнице нет сети, нет `node`, нет
`npm`, нет Gradle, нет устройства. Он пишет код и отдаёт диффом.

Следствие: **любая правка нативного кода приходит непроверенной**. Приёмка — на
стороне Claude, и только сборкой, а не чтением.

Практическое правило: **не докладывать «готово» по диффу**. Собрать, поставить,
запустить, посмотреть глазами. Три раза за день этот порядок ловил то, что
выглядело безупречно в коде.

## Как запускать

Обязательные флаги:
- `--skip-git-repo-check` — папка может не быть доверенной;
- `< /dev/null` — иначе блокируется на stdin;
- `-s read-only` для критики, `-s workspace-write` для работы;
- `-c tools.web_search=true` — **без него веб-поиска нет**, а прямого интернета в
  песочнице нет вообще: `curl` падает с `SEC_E_NO_CREDENTIALS`;
- `-c model_reasoning_effort="high"` для сложных задач.

**Промпт передавать файлом**, не строкой в двойных кавычках:
```
PROMPT=$(cat task.txt) && codex exec ... "$PROMPT"
```
Иначе bash попытается выполнить обратные кавычки внутри текста и всё сорвётся с
`unexpected EOF while looking for matching`.

## Что Codex делает хорошо

Статический анализ, поиск по документации, аккуратная работа с текстом,
честные отчёты о том, чего не смог. Он **не приписывает себе успех**: если не
запустил проверку — так и пишет.

Дважды поправил ошибочную гипотезу Claude, и оба раза был прав. Критику стоит
заказывать отдельным проходом `-s read-only` — она содержательная.

## Где Codex ошибается

- **Пишет по памяти, если не потребовать источник.** Предложил модели 2024 года,
  когда на дворе 2026. Требовать веб-поиск явно.
- **Ошибается в отчёте о состоянии файловой системы.** Заявил, что каталогов
  `.cxx` нет — они были, и именно в них сидела причина пяти падений подряд.
  Проверять его утверждения о файлах самостоятельно.
- **Не видит ограничений API, которых нет в документации.** Пример: имя ключа
  `expo-secure-store` допускает только `[A-Za-z0-9._-]`, а он записал
  `@life-coach/github-token`. Код выглядит нормально, падает при записи.

## Ловушки окружения

**Git Bash подменяет пути.** `adb pull /sdcard/...` превращается в
`C:/Program Files/Git/sdcard/...`. Лечится `MSYS_NO_PATHCONV=1` **префиксом
команды**, не через `export` в скрипте — через export не работает.

**PowerShell портит бинарники редиректом.** `adb exec-out ... > file.png` даёт
UTF-16 с BOM. Тянуть бинарное — через файл на устройстве и `adb pull`.

**Metro держит хендлы в node_modules.** Gradle падает на удалении `libc++_shared.so`.
Остановить Metro перед сборкой.

**Смена набора ABI ломает инкрементальную упаковку.** После правки
`reactNativeArchitectures` удалять `app/build`, иначе `packageDebug` падает.

**Протухшие `.cxx` переживают `gradlew clean`.** После смены версии нативной
зависимости удалять `.cxx` во **всех** пакетах, а не в тех, что кажутся
затронутыми: ссылку на старый хэш держат и соседи.

## Правила, выведенные из ошибок

1. **Требовать источник, а не память.** «Проверь веб-поиском и дай ссылку».
2. **Требовать негативный тест.** Проверка, которая всё пропускает, ничего не
   доказывает. Заказывать вместе с задачей: «подай на вход заведомо неверное и
   убедись, что отвергнуто».
3. **Синхронизировать генератор и сгенерированное.** Если правка в
   `android/`, а есть config plugin — править оба, иначе `prebuild` откатит.
4. **Просить назвать настоящую причину, а не первую строку ошибки.** Сообщение
   часто маскирующее: «restricted method in System» на деле было JDK 25 и Prefab.
5. **Не глушить симптом.** Формулировать прямо: «чини причину, не подавляй
   предупреждение».
