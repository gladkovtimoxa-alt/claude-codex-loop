# Инструменты и скрипты

Рабочие команды, выверенные на практике. Каждая учитывает ловушку, на которой
мы уже спотыкались — подробности в `../data/defects.jsonl`.

## Что чем запускать

| Задача | Оболочка | Почему именно она |
|---|---|---|
| Gradle, сборка | **PowerShell** | из Git Bash `cmd /c gradlew.bat` не находит рабочий каталог |
| `adb` с путями на устройстве | **PowerShell** либо Bash с `MSYS_NO_PATHCONV=1` **префиксом** | Git Bash подменяет `/sdcard/...` на `C:/Program Files/Git/sdcard/...`; через `export` переменная НЕ работает |
| Вытянуть бинарный файл | Bash или `adb pull` | PowerShell портит бинарники редиректом `>`, отдаёт UTF-16 с BOM |
| Запуск Codex | Bash | промпт передавать файлом, не строкой |
| `sh -n`, `bash -n`, любой шелл-скрипт | **только Bash** | голое имя `bash` из PowerShell резолвится в launcher WSL (`System32\bash.exe`), а дистрибутива нет: вместо вывода приходит ссылка на Microsoft Store. Git Bash стоит, но лежит по другому пути. Из PowerShell — только полным путём `C:\Program Files\Git\bin\bash.exe` |

## Файлы

- `build-release.ps1` — сборка автономного APK
- `install-and-check.ps1` — установка и проверка, что приложение реально поднялось
- `codex.sh` — запуск Codex с обязательными флагами
- `emulator.sh` — поднять эмулятор как устройство на 8 ГБ
- `tap-by-text.sh` — атомарный дамп UI + тап по тексту/content-desc (без устаревших координат)
- `watch-jslog.sh` — ловля JS-логов на реальном устройстве (увеличивает буфер, фильтрует по тегу)
- `validate-memory.py` — проверка `data/defects.jsonl` **перед** коммитом: битый JSON, пустые обязательные поля, дубли `symptom`
- `fix-jsonl-escapes.py` — починка escape-последовательностей; на неоднозначных случаях отказывается угадывать
- `net-reach.sh` — матрица достижимости TCP с телефона через `nc` (не `/dev/tcp`, его в Android sh нет)
- `host-alive-layer.sh` — на каком уровне отказал узел: сеть, ядро или процессы
- `prod-preflight.sh` — **шлюз** перед действием на боевой машине: снимает состояние и отказывает кодом возврата (`1` не потянет, `2` состояние не снято). Не памятка: памятку надо вспомнить, а вспомнить не выходит

## Правила, которые экономят часы

- **Конфиг механизма не доказывает существование механизма.** Проверять тремя
  командами: установлен ли инструмент, есть ли планировщик, проходит ли пробный
  прогон. Чтение конфига не заменяет ни одну из трёх.
- **Не строить план на своей же непроверенной записи.** Предположение,
  записанное в память как факт, уводит в сторону на сутки и хуже отсутствия
  записи — ему верит завтрашний ты. Отделять проверенное от предположенного
  прямо в тексте.
- **Смонтированный том не заставляет процесс перечитать файл.** Дескриптор
  открыт до перезагрузки конфигурации: обновление пройдёт, а наружу пойдёт
  старая версия — молча и надолго. Нужен хук на само обновление, и сперва
  список тех, кто артефакт реально читает.
- **Общее правило-перенаправление держать внутри своей ветки.** Пока оно на
  уровне блока, оно выполняется раньше выбора конкретной ветки, и никакая
  частная не выиграет.
- **Служебный код ответа легко принять за результат.** Отказ обслуживать
  запрос приходит в том же формате, что и находка. Уже второй случай за сутки —
  прежде чем радоваться найденному, проверить, не служебный ли это код.
- **Репутация и доступность — разные проблемы.** И не отвергать решение
  владельца из-за неверного объяснения: сперва проверить, нет ли другой
  причины, которая делает это решение правильным.

- **«Полный доступ» — это мнение владельца, а не полномочия ключа.** Права у
  поставщиков гранулярные: ключ бывает широким на чтение и при этом лишённым
  одного конкретного права на запись. Проверять КАРТОЙ операций — отдельно
  чтение, отдельно запись — и отвечать дословным отказом службы, а не спорить
  о словах.
- **Структура файла с учётными данными выдаёт его назначение.** Идентификатор
  доступа + секретный ключ + S3-совместимый адрес — это объектное хранилище,
  а не управление доменами. Прочитать поля до того, как перебирать вызовы.
- **Разделять адресацию и аутентификацию при утечке.** Если утёк адрес с
  токеном, менять надо адресный токен, а не ключи подключения: утёкшая ссылка
  умирает (404), живая сессия человека не прерывается. Проверять фактом:
  старый адрес 404, новый 200, трафик в журнале не прервался.
- **Секрет, попавший в переписку, скомпрометирован** — независимо от того, кто
  его туда положил. Прямо назвать, что утекло, и что именно отзывать. И
  сказать, какие из присланных ключей вообще не нужны для задачи.

- **Мешает защитный порог — он почти всегда прав.** Сверка упиралась в лимит
  удалений и не включалась. Соблазн был поднять порог; на деле лишними были
  записи, созданные руками в обход штатного механизма. Чинить данные, а не
  защиту. Перед удалением на бою доказывать неиспользуемость по журналам,
  **включая архивы за прошлые дни**.
- **Ноль совпадений по имени домена ≠ нет трафика.** QUIC и HTTP/3 ходят по
  IP. Искать по диапазонам адресов, а не по именам — особенно прежде, чем
  спорить с человеком о том, что он видел своими глазами.
- **Транспорт готов только после трафика реального устройства.** Свои пробы
  доказывают исправность тракта, но не пригодность для клиента: у него другая
  сеть, оператор и клиентский стек. Признак настоящего переключения — старая
  сессия замолчала, а не идёт параллельно.
- **Разное поведение операторов при одном конфиге = фильтрация по сигнатуре.**
  Не искать причину у абонента, если у другого оператора тот же конфиг
  работает. Лечится сменой транспорта, а не подкруткой параметров.

- **«Подключено» не значит «авторизовано».** Рукопожатие транспорта
  завершается ДО проверки пользователя, поэтому клиент показывает успех и
  считает байты, пока сервер молча отбрасывает сессию. Перед выдачей любой
  конфигурации проверять, что её идентификатор реально зарегистрирован на
  сервере. Пусто — конфигурация мёртвая.
- **Выдача и регистрация — разные места, они расходятся.** Признак в
  настройках («новый транспорт включён») не гарантирует, что серверная
  сторона регистрирует клиента именно там. Проверять обе стороны на
  СВЕЖЕсозданной записи, а не на старых, попавших туда вручную.
- **Читать существующий служебный скрипт до того, как изобретать вызов.**
  Рабочий формат и грабли обычно уже описаны комментарием внутри него.
  Пропуск этого шага стоил часа на «команда вернула 0, но ничего не сделала».
- **Параметризованный скрипт не безопасен для любого значения параметра.**
  Запуск с другим значением собрался удалить всех пользователей, потому что
  источник данных отдаёт жёстко зашитое значение для всех записей. Всегда
  пробный прогон и чтение того, что он собрался удалить.
- **Падает только твой пробник — чини пробник.** Если через систему идёт
  живой трафик и он успешен, а отказ получаешь только ты, сломан инструмент
  диагностики, а не система.

- **Прямое указание «прочитай всё» не заменять выборкой.** Подмена чтения
  документации веб-поиском один раз дала уверенно НЕВЕРНЫЙ вывод («такой
  возможности нет»), который блокировал бизнес-задачу. Цена не в лишней
  работе, а в ложной уверенности.
- **Документация-приложение: искать встроенный контракт.** Если сайт отдаёт
  только вводную страницу и не даёт оглавления — сохранить страницу ЦЕЛИКОМ
  и вынуть из неё машинную спецификацию, считая скобки от якоря до баланса.
  Сохранение «только HTML» не годится: контракт лежит внутри скриптов.
  Так из семи разделов, видимых поиском, нашлось четырнадцать методов.
- **Справочник по API — генерировать, а не перепечатывать.** Рукописный
  расходится с источником на первой правке и становится вреднее отсутствия,
  потому что ему верят.
- **Проверять доступность чужого API читающим методом.** Список почти всегда
  безопаснее создания и отвечает на тот же вопрос, ничего не создавая в бою.
- **Скользящее окно не отвечает на вопрос «что нового».** Одна и та же запись
  выглядит новой при каждом опросе, пока не выйдет за границу. Нужен якорь:
  время выкатки или максимальный обработанный идентификатор.

- **Не приделывать `|| echo 0` к `grep -c`.** У него код возврата означает
  «нашлось ли», а не «сработал ли»: при нуле совпадений он ПЕЧАТАЕТ `0` и
  выходит с кодом 1, поэтому запасная ветка дописывает второй ноль и вывод
  превращается в мусор. Для подсчёта — `... | wc -l`: всегда одно число и
  всегда код 0.
- **Перед подсчётом грепом распечатать первые строки источника.** Ноль
  совпадений от неверного шаблона неотличим от настоящей пустоты. Дважды за
  один час это выглядело как «данные потеряны»: сначала инструмент не умел
  читать тип объекта, потом вывод оказался с табуляцией вместо `Ключ = значение`.
- **Измерить ущерб до починки.** Отсутствие страховочного механизма и наличие
  ущерба — разные вещи. Сначала посчитать, кого именно не хватает, и только
  потом решать. Автоматику, которая УДАЛЯЕТ, в одиночку не включать.

- **Счётчик anti-thrash снимает не любой прогон.** Запуск через Bash и
  перечитывание файла его НЕ сбрасывают — сбрасывает только запуск через
  **PowerShell**, тем же инструментом, которым реализован хук. Совет в тексте
  самого хука («or re-Read it») не работает. И отбитая правка **тоже**
  увеличивает счётчик: повтор сразу после отбоя углубляет яму, а не топчется
  на месте. Порядок: отбой → один запуск через PowerShell → ОДНА правка.
- **Перед копированием файла на бой — сверить содержимое, а не размер.**
  Скачать боевую версию и сравнить построчно: в расхождении должны быть
  ТОЛЬКО твои строки. Любая лишняя — правка, сделанная прямо на сервере,
  которую копирование сотрёт молча. Размер файла не годится: он одинаково
  меняется от твоей правки, от чужой и от обеих сразу.
- **Запрет переноса не делает строку уже.** Строка переносится, потому что
  не помещается; запретив перенос, получишь горизонтальное переполнение —
  то же самое, но незаметнее. Ставить запрет только В ПАРЕ с уменьшением
  размера или расширением контейнера. Общий вид ошибки: лечить видимое
  следствие (перенос, обрезание, скролл) вместо причины (не влезает).
- **Просят добавить то, что уже есть, — ищи настоящую нехватку.** Просьба
  указывает область, а не действие. Смотреть, что в этой области менялось
  недавно: заголовок — это обещание, а подтверждают его блоки ниже, и после
  смены обещания страница начинает противоречить себе молча.
- **Память проверять ДО коммита, а не после.** Один раз сломанный
  `defects.jsonl` уже уехал в удалённый репозиторий именно потому, что
  проверка стояла после отправки. Порядок: `python scripts/validate-memory.py
  data/defects.jsonl` → и только при коде 0 `git commit`.
- **Валидатор не должен принуждать к выдумке.** `found_by` и
  `first_hypothesis` необязательны: часть записей — общие наблюдения и
  решения владельца, у которых их не было. Требовать эти поля — значит
  дописывать их задним числом и портить память ради зелёной галочки.
- **Отрицательный контроль.** Проверку тракта, доступа или самого
  инструмента сопровождать второй пробой с заведомо неверным параметром.
  Если «работает» и с ним — проверка меряет не то, что ты думаешь.
- **Положительный контроль — парный и обязательный.** Новый пробник гонять
  на заведомо ИСПРАВНОМ объекте, а не только на сломанном. На сломанном
  ложный пробник выглядит правым по совпадению: там любая проба показывает
  беду, и верную логику от неверной отличить физически нельзя. Различает
  только исправный объект — он обязан дать вердикт «здоров». Два прогона
  подряд, оба вердикта в отчёт. Это шаг ПРИЁМКИ инструмента, а не понимание:
  правило, лежащее в памяти, само себя при сочинении кода не применит.
- **Отправку сверять по SHA.** Надпись `Everything up-to-date` уже приходила
  от двух разных сбоев. После push сравнивать локальный `HEAD` с веткой на
  удалённом и отправлять текущую ветку, подставляя её имя.

**Перед сборкой останови Metro** — он держит хендлы в `node_modules`, и Gradle
падает на удалении `libc++_shared.so`.

**После смены набора ABI удали `android/app/build`** — инкрементальная упаковка
ссылается на исчезнувшие архитектуры.

**После смены версии нативной зависимости удали `.cxx` во ВСЕХ пакетах**, а не
только в изменённых: ссылку на старый хэш держат и соседи.

**Не применяй `subst`** к каталогу проекта — одни и те же файлы становятся
доступны по двум путям и портят инкрементальный кэш Kotlin.

**На устройство пользователя ставь только release.** Debug не содержит JS и
требует Metro на компьютере: при каждом запуске без него — красный экран.

**Перед живым тестом на реальном телефоне увеличь буфер logcat** (`adb -s
<dev> logcat -G 16M`) и фильтруй по тегу (`logcat ReactNativeJS:V *:S`), не
grep по всему потоку. У реальных телефонов (особенно MTK) буфер бывает 256 КБ
и системный спам вытесняет JS-логи за секунды — используй `watch-jslog.sh`.

**Перед первым `git add -A` на свежем дереве сделай dry-run** (`git add -A -n`)
и `du -sh` по крупным каталогам. Легко случайно закоммитить `android/app/build`
(гигабайты) и `.models/` (скачанные GGUF/Vosk) — они должны быть в `.gitignore`.

**`fix-jsonl-escapes.py <файл> [--dry-run]`** — чинит невалидные JSON-escape
в JSONL-памяти. Повод: windows-путь и регулярка, записанные с одиночными
обратными слэшами, делают строку нечитаемой, а читатель, собирающий список
через генератор, падает целиком и теряет **всю** память, а не одну запись.
Скрипт удваивает только «голые» слэши, валидные записи не трогает, перед
записью кладёт бэкап. Прогонять после каждого дописывания в `data/`.

Читать память построчно с `try/except`, а не списком — тогда одна битая
запись не уносит остальные.

**`net-reach.sh [порт] [ip...]`** — матрица достижимости TCP с подключённого
телефона. Отвечает на вопрос, который надо задавать ПЕРВЫМ при жалобе «не
работает в сети»: сломан наш сервис или в этой сети вообще ничего не
открывается. Печатает вердикт — белый список оператора, мёртвая сеть или
нормальная линия.

Меряет через `nc`, а не через `/dev/tcp`: последнего в Android sh **нет**,
и попытка им пользоваться даёт таймаут по всем целям сразу — отказ инструмента
неотличим от искомого «всё заблокировано». В наборе всегда держится заведомо
рабочая цель: если и она SHUT, сломан инструмент, а не сеть.

Снимать при **выключенном VPN**, иначе меряется туннель.

## «Сервер не отвечает» — это три разные аварии

`host-alive-layer.sh <адрес> [рабочий_порт] [заведомо_закрытый_порт]`

Отделяет мёртвую сеть от мёртвого ядра и от мёртвого userland. Круг уже был
потерян на том, что задушенную нехваткой памяти машину приняли за
отфильтрованную: ping шёл, порты соединение принимали, а SSH обрывался на
`banner exchange` и сайт отдавал `000`.

Решают две пробы, и обе неочевидные:

- **Заведомо ЗАКРЫТЫЙ порт.** Честный мгновенный отказ доказывает, что ядро
  отвечает осознанно, а значит фильтра нет. Файрвол так не умеет — он молчит
  одинаково на всех портах и выбирает весь таймаут. Отказ от фильтра
  различаются **по времени ответа**, кода возврата для этого мало.
- **Чтение БАЙТОВ с рабочего порта.** Ограничиться установкой соединения
  нельзя: соединение принимает ядро, и задушенная машина принимает его точно
  так же, как здоровая. Первая версия скрипта именно на этом и врала — на
  здоровом узле выдавала вердикт «процессам не достаётся ресурсов».

Вердикт «ядро живо, userland мёртв» лечится **снятием питания**. Мягкая
перезагрузка на такой машине зависает: она требует, чтобы userland отработал
остановку сервисов, а он и есть то, что стоит колом. И факт нажатия кнопки
ребут не доказывает — доказывает только `uptime` после подъёма.

Отсюда же правило про диагностику на тесной машине: команда, поднимающая
рантайм приложения (консоль фреймворка, ~25 МБ), на узле с одним ядром и
гигабайтом памяти сама становится частью аварии. Читать данные напрямую
клиентом базы, а таймаут ставить **на удалённой стороне** — обрыв на своей
не убивает процесс там, он остаётся сиротой и продолжает жрать ресурсы.

## Где начало аварии: искать перелом, а не пик

Самое громкое событие в журнале почти всегда следствие, и разрыв бывает в
десятки минут. В разборе 28.08 первое убийство по нехватке памяти случилось
на **15 минут позже**, чем система реально встала — отсчёт от него увёл бы
искать виновника в окне, где его уже нет.

Перелом виден в скучном признаке: **регулярная работа перестала завершаться.**
Взять периодическую задачу и посчитать поминутно «запущено против завершено»:

```bash
journalctl -b -1 --no-pager -t CRON --since '<до>' --until '<после>' \
 | awk '{split($3,t,":"); m=t[1]":"t[2]}
        /session opened/{o[m]++} /session closed/{c[m]++} {seen[m]=1}
        END{for(k in seen) printf "%s открыто=%d закрыто=%d\n", k, o[k], c[k]}' | sort
```

Минута, где завершения обнулились при ненулевых запусках, и есть точка отсчёта.

Дальше — **отрицательный контроль по времени**: посмотреть тот же процесс за
предыдущие сутки. Если вчера он отработал штатно, виноват не он сам, а условие,
изменившееся сегодня.

## Автономность: слои различать по тому, чей ресурс они тратят

Сторож **внутри** системы сам нуждается в том ресурсе, исчерпание которого
призван лечить, и потому отказывает ровно тогда, когда нужен. Это свойство
схемы, а не настройки.

| Слой | Где работает | Когда действует |
|---|---|---|
| Запас (своп, лимиты) | внутри | до беды |
| Потолок на группу | внутри | до беды |
| Отбор по давлению | внутри | пока ресурс ещё есть |
| Перезагрузка зависшего | **только снаружи** | после отказа |

Обещать автономность внутренним сторожем — обманывать себя. И проверять
доступность аппаратного сторожа заранее: на виртуальных площадках его часто
нет вовсе, включать оказывается нечего.

Отдельно: **автоматическое восстановление, не отличающее виновника от
пострадавшего, при исчерпании общего ресурса ускоряет падение** — оно
освобождает ресурс ровно для того, кто аварию устроил. Проверять не
«перезапустился ли», а «убыл ли виновник».

## Замены для команд, уходящих в удалённый шелл

Обёртка PowerShell → `ssh.exe` съедает кавычки, и bash на той стороне видит
выражение без них. Знать это **недостаточно** — за один час я четырежды подряд
подставил очередную конструкцию, которая этого не переживает. Ниже таблица
замен; левая колонка ломается молча или мусором, правая проверена в работе.

| Не доезжает | Работает вместо |
|---|---|
| `curl -w "%{speed_download}"` — фигурные скобки съедаются, в консоль летит бинарь | `curl -s URL \| dd of=/dev/null bs=1M 2>&1 \| tail -1` |
| `grep -E "A\|B"` — вертикальная черта разбирается как конвейер | `grep -e A -e B` |
| `awk "{print \$2}"` — знак поля и скобки не переживают | утилита, считающая нужное сама |
| два снимка счётчиков + вычитание | `nstat > /dev/null; sleep N; nstat` — печатает дельту сам |
| `tcpdump ... \| awk ... \| sort` на лету | `tcpdump -w /tmp/c.pcap`, затем отдельные `tcpdump -r /tmp/c.pcap "фильтр" \| wc -l` |
| `echo "текст (в скобках)"` | без круглых скобок вовсе |

Общее правило: **не отправлять в удалённый шелл конструкции со скобками,
вертикальной чертой и знаком поля.** Если выражение их требует — значит нужна
другая утилита, которой такой синтаксис не нужен.

## Диагностика узла-пересыльщика: что доказывает работу, а что нет

Порядок проверки, снявший реальную аварию (правила верные, узел не пересылает):

```bash
nstat > /dev/null; sleep 20; nstat | grep -e Forw -e InReceives -e InDeliver -e UdpNoPorts
```

Читается так: `IpInDelivers` примерно равен `IpInReceives` при нулевом
`IpForwDatagrams` — **узел не пересылает ничего**, всё уходит в локальную
доставку. Растущий `UdpNoPorts` подтверждает: пакеты умирают на закрытом порту.

**Нулевой счётчик самого правила ничего не доказывает** — у него два
противоположных смысла: «не совпадает» и «совпало однажды, дальше поток идёт
мимо правил». Различает только обратный кортеж записи состояния:

```bash
conntrack -L -p udp | grep <адрес_источника>
```

Если после `[UNREPLIED]` стоит адрес САМОГО УЗЛА — трансляция не применилась.
Если адрес назначения — применилась. Лечение — сброс застрявших записей,
не переписывание правил:

```bash
conntrack -D -p udp -s <адрес_источника>
```

Записи не истекают сами: клиентские пакеты поддержки каждые 25 секунд
обновляют таймер бесконечно. **После любой правки правил пересылки на живом
узле сбрасывать записи состояния для затронутых потоков** — иначе правка ляжет
верно, а сервис останется лежать.

Пакета `conntrack` может не быть в системе, а `/proc/net/nf_conntrack` может
отсутствовать при загруженных модулях — обе проверки тогда молча возвращают
пустоту, и это **не** доказывает отсутствия потоков. Ставится через
`apt-get install -y conntrack`.

Итоговое доказательство берётся **на дальней стороне**, не на правленом узле:
свежее рукопожатие с нужным адресом и портом в источнике.

## Публикация этого скила — только проекцией

**Этот каталог не отдельный репозиторий.** Корень лежит уровнем выше
(`C:/Users/ass/Desktop/000`), а сюда скил попадает подкаталогом. В свой
репозиторий на GitHub он уезжает проекцией. Проверить, где ты на самом деле:

```bash
git rev-parse --show-toplevel   # корень — не этот каталог
git rev-parse --show-prefix     # skills/claude-codex-loop/ — значит ты не в корне
```

Список удалённых, показанный отсюда, принадлежит **монорепозиторию**. Поэтому
обычная отправка выглядит очевидно правильной и при этом залила бы в репозиторий
скила всё дерево целиком:

```bash
git push loop main              # НЕВЕРНО — отправит весь монорепозиторий
```

Верно — из корня и с префиксом:

```bash
cd /c/Users/ass/Desktop/000
git subtree push --prefix=skills/claude-codex-loop loop main
```

**Отказ «ветка позади удалённой» здесь не значит расхождения версий** — он
одинаково означает и обращение не к тому репозиторию. Подсказка git слить
удалённые изменения в этом случае **разрушительна**: она втянет переписанную
историю проекции обратно в монорепозиторий. Признак подмены: на удалённом
коммиты с теми же сообщениями, но другими хешами.

### Проверять синхронность по содержимому, а не по истории

Хеши проекции создаются заново и с локальными не совпадают **по построению**.
Поэтому сравнение диапазоном всегда покажет коммиты неотправленными —
и при успехе, и при провале:

```bash
git log --oneline loop/main..HEAD   # бесполезно на проекции, ответ всегда один
```

Работает только чтение содержимого прямо из удалённой ветки:

```bash
git fetch loop main
git show loop/main:data/defects.jsonl | grep -c .        # число записей
git show loop/main:data/defects.jsonl | tail -3          # последние записи
git show loop/main:scripts/README.md | grep -c "<раздел>"
```

Проверка, дающая одинаковый ответ при успехе и при провале, проверкой не
является — и повторная отправка из-за неё это лишний риск.
